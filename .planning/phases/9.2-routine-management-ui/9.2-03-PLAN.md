# Phase 9.2 Plan 3: Fix Routine Save State Synchronization

**Fix state synchronization bug where RoutineEditor doesn't update when switching days, causing save failures and data loss**

## Problem

The RoutineEditor component has a critical state synchronization bug:
- When users switch days, the `initialSteps` prop changes
- But the component's local `steps` state doesn't update
- This causes the component to display stale data
- Saving writes the wrong data to the database
- Users lose their changes or save to the wrong day

## Root Cause

Missing `useEffect` hook to synchronize local state when props change.

## Tasks

### Task 1: Add state synchronization to RoutineEditor

**File**: `app/skincare/routines/components/RoutineEditor.tsx`

**Changes**:
1. Add `useEffect` hook after existing state declarations
2. Dependencies: `[initialSteps, dayOfWeek, timeOfDay]`
3. Inside effect:
   - Update `steps` state to match `initialSteps`
   - Reset `hasChanges` to `false`
   - Reset `editingId` to `null`
   - Reset `editText` to empty string

**Code**:
```typescript
useEffect(() => {
    setSteps(initialSteps);
    setHasChanges(false);
    setEditingId(null);
    setEditText('');
}, [initialSteps, dayOfWeek, timeOfDay]);
```

**Why**: Ensures component always displays correct data for selected day and prevents editing wrong step after navigation.

### Task 2: Improve error handling in upsertRoutine

**File**: `app/skincare/routines/actions.ts`

**Changes**:
1. Add detailed error logging before throwing
2. Log the full error object with context
3. Include dayOfWeek, timeOfDay, and steps count in error message

**Code**:
```typescript
if (error) {
    console.error('Failed to save routine:', {
        error,
        dayOfWeek,
        timeOfDay,
        stepsCount: steps.length,
        message: error.message
    });
    throw new Error(`Failed to save routine: ${error.message}`);
}
```

**Why**: Better debugging information when save operations fail.

## Verification

Manual testing required:

1. **Basic save**: Add step, save, refresh → step persists
2. **Day switching**: Save on Monday, switch to Tuesday, back to Monday → Monday data intact
3. **Multiple time periods**: Save morning and night separately → both persist independently
4. **Edit operations**: Edit step, save, refresh → edited text persists
5. **Delete operations**: Delete step, save, refresh → step is gone
6. **Reorder operations**: Reorder steps, save, refresh → new order persists

- [ ] Switching days shows correct data for each day
